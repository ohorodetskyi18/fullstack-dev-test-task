  Що означає завдання

  Потрібен один скрипт, який з нуля піднімає блог Ghost на VPS у Hetzner. При
  цьому на сервер не можна потрапити по SSH з інтернету: на публічній IP не
  слухає жоден порт. Відвідувачі заходять на блог через тунель, адміністратор
  теж заходить через тунель. Це роблять або сервісом провайдера (Cloudflare
  Tunnel, Tailscale), або окремою програмою на сервері (cloudflared,
  tailscaled). Здогадуюсь, що «(provider/app)» означає саме це. «no publish SSH»
  — найімовірніше, опечатка в «no public SSH».

  У чернетці обрано Tailscale:
  - Tailscale Funnel публікує блог за HTTPS на
    https://ghost-blog.<tailnet>.ts.net. Власний домен не потрібен.
  - Tailscale SSH дає адмінський доступ тільки з вашого tailnet.
  - Обидва з'єднання вихідні з VPS, тому вхідні порти можна закрити повністю.

  Що перевірте самі в консолі Tailscale

  1. Auth key (Settings → Keys):
  - Tags = tag:ghost. Це обов'язково, бо Funnel і SSH-правила прив'язані до
    тегу.
  - Pre-approved увімкнено.
  - Ephemeral вимкнено.
  - Reusable вимкнено. Одноразовий ключ безпечніший, але якщо деплой впаде, для
    повтору знадобиться новий ключ.

  Якщо тег не задали, створіть ключ заново після кроку 2. Тег не з'явиться у
  списку, доки його немає в ACL.

  2. ACL (Access controls): додайте в policy file
  "tagOwners": { "tag:ghost": ["autogroup:admin"] },
  "nodeAttrs": [ { "target": ["tag:ghost"], "attr": ["funnel"] } ],
  "ssh": [
    { "action": "accept", "src": ["autogroup:admin"], "dst": ["tag:ghost"],
  "users": ["root"] }
  ]
  Якщо секції ssh чи nodeAttrs уже є, допишіть елементи у наявні масиви, а не
  створюйте другу копію. Стандартне правило ssh з autogroup:self не дає доступу
  до серверів із тегом, тому потрібне окреме правило.
